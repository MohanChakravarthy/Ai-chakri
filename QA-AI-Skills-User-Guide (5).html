QA AI Skills: user guide

Turn your test cases into clean, working Robot Framework scripts that reuse your team's existing keywords and locators. Install once, build the knowledge once, then generate scripts with one short command in your editor's AI chat.

Devin DesktopVS Code + GitHub CopilotVS Code + Claude Code SeleniumLibraryBrowser library

1Overview

What the skills do and what you get.

Learns your repo

Reads your tests, keywords, locators and run settings once and keeps them as "knowledge".

Writes the script

Turns a test case into a Robot Framework test, reusing your existing keywords and locators first.

Proves it works

Runs the test in a real browser. A test counts as verified only after it passes twice.

Asks very little

Normally only which environment to use, once. It shows its understanding of each test case for your OK.

There are two commands, the same in all three editors:

How to type the commandsIn Devin Desktop, start with @, for example @qa-knowledge-setup build. In VS Code (GitHub Copilot or Claude Code), start with /, for example /qa-knowledge-setup build.
CommandUse it to
qa-knowledge-setupTeach the AI your repository (run once, then refresh after big changes).
robot-script-generatorCreate and prove scripts from your test cases.

3Install

About 5 minutes, once per computer and repository.

  1. Copy the folder into your QA repoUnzip qa-ai-skills.zip so that the qa-ai-skills folder sits directly in the root of your QA repository, next to your tests.
  2. Open a terminal in the root of your QA repoIn your editor: Terminal > New Terminal. Make sure the path ends with your repo's folder name.
  3. Run the installer
    SystemFirst timeLater, from any folder in the repo
    Windows (PowerShell or Command Prompt).\qa-ai-skills\qa-ai-setup installqa-ai-setup install
    macOS or Linuxsh qa-ai-skills/qa-ai-setup.sh installqa-ai-setup install
  4. Answer two short questionsPick your editor with the arrow keys and Enter. Then choose whether to connect qTest now (optional; you can skip it and do it later).
  5. Wait for "Setup complete"The installer shows one line with a spinner and a percentage while it works. At the end it says Setup complete. Everything is ready and working.
  6. Restart your editorClose it completely and open it again on your QA repo, so it loads the new AI tools and commands.

What the installer does for you

  • Installs the Robot Framework MCP and the Playwright MCP only if they are missing.
  • Sets up only the editor you chose, and adds the two commands to its chat.
  • Keeps your own editor settings and AI tools exactly as they are, and backs up any file before changing it.
  • Connects qTest if you choose to (read-only). Your token is typed hidden and stored only in your local .env.
  • Adds the AI's working files to .gitignore, so nothing private is committed by mistake.
  • Starts every AI tool once and runs a configuration check to prove everything works.
Running it again is safeIf everything is already set up, it says Setup is already complete. Nothing to do. If something is missing, it repairs only that. To set everything up again on purpose: qa-ai-setup install --force.

4Check it works

Two quick checks after installing.

  1. Run the checkqa-ai-setup check starts the AI tools and runs the configuration check without changing anything. It ends with Configuration check passed: everything is working.
  2. Find the commands in your editorOpen the AI chat and type @ (Devin Desktop) or / (VS Code). You should see robot-script-generator and qa-knowledge-setup.
    • Devin Desktop: pick qa-ai-skills/skills/robot-script-generator.md or qa-knowledge-setup.md from the list (they also appear as skills under /).
    • VS Code with GitHub Copilot: switch the chat to Agent mode first.
    • VS Code with Claude Code: approve the project's AI tools the first time Claude Code asks.

5Build the knowledge

Do this once per repository before generating scripts. Afterwards, refresh it when the repo changes.

How to type the commandsIn Devin Desktop, start with @, for example @qa-knowledge-setup build. In VS Code (GitHub Copilot or Claude Code), start with /, for example /qa-knowledge-setup build.
CommandWhat it doesExample
qa-knowledge-setup buildLearns the whole repository: application screens and flows, keywords, locators and run settings.qa-knowledge-setup build
qa-knowledge-setup build <folder or suite>Learns one folder or suite file and everything it uses. Adds to the existing knowledge.qa-knowledge-setup build tests/payments
qa-knowledge-setup build <topic>Learns the tests about one topic (matched by file, test name, tags or documentation).qa-knowledge-setup build addresses
qa-knowledge-setup refreshUpdates only what changed since the last build. Also continues a build that was interrupted.qa-knowledge-setup refresh
qa-knowledge-setup rebuildBuilds everything again from scratch.qa-knowledge-setup rebuild
qa-knowledge-setup rebuild <scope>Builds one folder, suite or topic again from scratch; the rest is kept.qa-knowledge-setup rebuild tests/kyc
qa-knowledge-setup devAdds or updates the application's development repositories (optional, read-only) for stronger knowledge.qa-knowledge-setup dev
qa-knowledge-setup statusShows how complete and up to date the knowledge is. Changes nothing.qa-knowledge-setup status

What happens

The AI shows a 7-step checklist and works through it without stopping. Big repositories are built in batches, most-used areas first, with one progress line per batch.

Development repositories (optional)

At the start of a build, the AI asks once whether to include the application's source code. Paste the repository links, or choose No to skip. With the code included, the knowledge also knows real field IDs, dropdown options and validation messages, so new scripts need less exploring.

  • The code is only read: never changed, built or committed. It goes into a dev folder next to your QA repo.
  • Giving the same repository again does not clone it again; it just updates it to the latest code.
Good practiceCommit the qa-ai-data/knowledge folder so the whole team shares one knowledge base. Its temporary parts are git-ignored automatically.

6Generate scripts

Give a test case; get a proven script that reuses your existing keywords and locators.

How to type the commandsIn Devin Desktop, start with @, for example @robot-script-generator TC-1234. In VS Code (GitHub Copilot or Claude Code), start with /, for example /robot-script-generator TC-1234.
CommandWhat it does
robot-script-generator TC-1234Finds test case TC-1234 in the repo's test case files and automates it.
robot-script-generator qtest TC-1234Fetches the test case from qTest (read-only), then automates it. Several IDs are allowed: qtest TC-1234 TC-1235.
robot-script-generator cases.md allAutomates every test case in a file, as one batch.
robot-script-generator cases.md first 10The first 10 test cases of the file. Also: next 10, 5-20, 3 7 9, TC-101 TC-102.
robot-script-generator cases.md failedRuns the failed or blocked test cases of the last batch again.
robot-script-generator check address type HOME is availableA plain request without a test case: the AI writes the steps, shows them, then automates them.
robot-script-generator cases.md TC-1234 mock <link>A new feature not released yet: builds the test against a mock screen, ready for the release.

Test case files it reads

AIDLC test case files, Spec Kit spec.md files (each acceptance scenario is one test case), hand-written .md or .txt files, Gherkin (Given / When / Then), tables, and .csv exports from qTest and other tools. If you have an Excel file, export it as .csv first.

What happens, step by step

  1. Understands the test caseReads it, finds how your team already does each step, and fills in obvious missing steps (such as logging in or opening the record).
  2. Shows you its understandingFor each test case where it added or clarified something, you see one card. Choose Looks right or type a correction.
  3. Asks for the environment, onceFor example QA or UAT. Your answer is remembered for next time. Production is never used.
  4. Writes and proves the scriptReuses your keywords and locators first, explores the live page only for new screens, proves every new locator, and runs the test in a visible browser.
  5. Hands it overA test that passes twice moves to verified. You get a short summary and are asked before anything is added to your suite, branched or committed.

How a generated script looks

Every reused team keyword is marked, so reviewers see at a glance what is existing and what is new:

*** Test Cases ***
TC-1234 Approve a submitted KYC case
    [Tags]    ai-generated    kyc
    # Step 1: Log in as the approver
    # Reused: Login To Portal (resources/common.resource)
    Login To Portal    ${APPROVER_USER}
    # Step 2: Open the client's case
    # Reused: Search Client (resources/client.resource)
    Search Client    ${CLIENT_SUBMITTED}
    # Step 3: Approve the case
    Click Approve Button
    Wait Until Page Contains    Case approved

7Your files and updates

Two folders sit at the root of your QA repo.

<your QA repo>/ qa-ai-skills/ the package: skills and tools. Safe to replace with a newer version. qa-ai-data/ YOUR DATA: knowledge, generated tests, results, backups. tests/ ... your team's files (never changed without your approval)

Updating to a newer version

  1. Replace the package folderReplace qa-ai-skills with the new one. Your data in qa-ai-data is not touched.
  2. Run the installerqa-ai-setup install applies the update.
  3. Refresh the knowledgeqa-knowledge-setup refresh applies any new knowledge rules.
Coming from an older version?Older versions kept the knowledge inside qa-ai-skills. Unzip the new package over the old folder (do not delete it first) and run qa-ai-setup install once. It moves your knowledge and tests to qa-ai-data. From then on, you can simply replace the folder.

8Troubleshooting

Every warning in the installer also prints its cause and fix. The full details are in qa-ai-data/results/setup-log.txt.

Installation

What you seeLikely causeWhat to do
Python was not foundPython is not installed or not on the PATHInstall Python 3.10 or newer (or ask IT), open a new terminal, run the installer again.
Robot Framework was not found in this PythonRobot is installed in a different Python or virtual environmentActivate your team's virtual environment, then run the installer again.
Node.js is missing or too oldNode.js below 18Install Node.js 18 or newer, open a new terminal, run the installer again.
Robot Framework MCP or Playwright MCP could not be installedNo internet access for pip or npm, or a company proxyAsk IT to allow pip and npm, or install the package the message names, then run the installer again.
Neither Chrome nor Edge was foundNo supported browserInstall Google Chrome or Microsoft Edge.
No .robot files found in this repositoryThe folder is not in the root of the QA repoMove qa-ai-skills to the repo root and run the installer from there.
qa-ai-setup is not recognisedThe terminal was opened before the first installOpen a new terminal, or use the first-time command from section 3.
The commands do not appear in the chatThe editor was not restartedClose the editor completely and open it again on the QA repo.

9Safety rules

Built into the skills. You do not need to remember them, but it helps to know them.

  • Test environments only. Anything that looks like production is refused.
  • Passwords and tokens come only from your vault, configuration or .env. They are never typed into the chat or shown.
  • Your team's tests, keywords and locators are never changed without proof and your approval.
  • Nothing is added to a suite, branched, committed or pushed without asking you first.
  • Development repositories, qTest and databases are only read, never changed.
  • Shared test data a test changes is put back at the end of the test.
  • Client data is never written into scripts, knowledge, logs or reports.
